# Paper scans — OCR fixtures

Photograph-like images of paper documents, for the OCR route added in
`ingest/ocr.py`. Generated by `scripts/gen_paper_scans.py`.

Each is rendered as a clean sheet and then degraded the way a phone camera
degrades a page: slight rotation, uneven lighting across the sheet, blur
and sensor noise. A crisp screenshot of text would be a useless fixture —
every backend reads one perfectly, so it proves nothing about the cases
that actually fail.

| File | Condition | Expected |
|---|---|---|
| `resignation-letter-photographed-clean.jpg` | Well lit, barely skewed | Full transcription |
| `performance-review-photographed-angled.jpg` | Rotated, uneven lighting | Full transcription; rating 4/5 |
| `offer-letter-photographed-poor-lighting.jpg` | Strong gradient, low contrast | Transcription; check the salary digits |
| `resignation-letter-photographed-very-faint.jpg` | Washed out near paper colour | ⚠ Edge case — see below |

> **Predicted, not measured.** These have not been run against a live OCR
> backend. Treat a mismatch as interesting rather than as a regression.

## The one worth watching

`resignation-letter-photographed-very-faint.jpg` is pushed to the edge of
legibility deliberately. A refusal there is a *correct* outcome — the
uploader is told the page is unreadable and can rephotograph it.

The failure to watch for is the opposite: a confident transcription with a
misread digit. `30 September` read as `20 September`, or a salary of
`128,000` read as `123,000`, produces a value that is structurally valid,
passes schema validation, and reaches a reviewer looking exactly like a
correct one. Nothing downstream can catch it, because nothing downstream
knows what the paper said.

That is the reason every fact staged from an OCR source is discounted
(`OCR_CONFIDENCE_SCALE`, currently 0.7) and the document carries an **OCR**
marker in the documents table. The discount does not detect the error; it
tells the reviewer which values deserve a second look.

## Setup

OCR needs a backend. With AWS already configured for Bedrock extraction,
there is nothing further to do — the same credentials, region and model are
reused, and `COMPANYSIM_OCR_PROVIDER` can stay unset.

| `COMPANYSIM_OCR_PROVIDER` | Needs | Notes |
|---|---|---|
| unset (auto) | — | Bedrock if AWS is configured, else a local Tesseract |
| `bedrock` | existing Bedrock setup | Best on skewed, messy or handwritten pages |
| `textract` | `textract:DetectDocumentText` | Cheaper, stronger on dense printed text |
| `tesseract` | Tesseract **binary** + `pip install pytesseract pillow` | Offline and free; right for bulk archives |
| `off` | — | Images are refused at upload |

Check what a running server resolved:

```bash
curl http://localhost:8611/llm/status
```

## What OCR changes, and what it doesn't

Paper is **not a second pipeline**. A photograph produces the same
`raw_text` a typed document would have, and then travels the identical
route: extraction, staging, human review, apply. OCR sits beside
`utf-8-sig` and `pypdf` as a decoder, not beside the LLM parser — putting
it anywhere else would open a second route into the database.

Three consequences worth knowing:

**Transcription happens once, at upload.** `raw_text` is stored on the
document row, so re-extracting a page never re-bills OCR. Tokens are
metered under the `ocr` feature in the usage panel.

**A scanned PDF now works.** A PDF with no text layer — what a scanner or a
phone's document mode produces — used to be refused outright. Its page
images are now transcribed instead. A PDF that *does* have a text layer
never calls OCR, so a born-digital file costs nothing.

**An unreadable page is rejected at the door**, not stored as an empty
document. A blank row would arrive at review looking like a successful
ingest that simply found nothing, which is the failure this pipeline works
hardest to avoid everywhere else.

## Suggested run-through

1. Upload `resignation-letter-photographed-clean.jpg` as a **resignation
   letter** with an as-of date. Confirm the row shows an **OCR** marker.
2. Extract it, then open the review panel and read the transcription back
   against the image — the point is whether the *email and date* survived,
   since those are what the extraction depends on.
3. Upload `performance-review-photographed-angled.jpg` and check the rating
   came through as 4, not 4/5 or 45.
4. Upload the very-faint letter last, and decide which outcome you got:
   refusal, correct transcription, or confident misreading.
