# Format stress corpus

37 documents that vary the **shape** of the input rather than the volume:
delimiters, encodings, locales, rating scales, date orders, page layout and
file type. One behaviour per file, and the filename states which — so a
results table reads without a legend.

The `sample-docs/` set above tests whether the pipeline extracts the right
*content*. This set tests whether it survives the *container*.

Generated by `scripts/gen_format_corpus.py`, grounded in org 9 "Meridian
Analytics" so that email matching genuinely exercises reconciliation.

> **Not yet executed.** These were generated but not run against a live
> extractor. The "expected" column is a prediction from reading the code,
> not a recorded result — treat a mismatch as interesting rather than as a
> regression. Rosters need no API key; everything else needs
> `COMPANYSIM_LLM_INGEST=1` and a configured provider.

## Two defects already confirmed by direct probing

These needed no upload — `ingest/rules_parser._coerce` was called directly.

| Input | Parsed as | |
|---|---|---|
| `1234,56` | **123456.0** | silent 100× error |
| `85.000,50` | **85.0005** | silent — a salary of 85 cents |
| `85 000,50` | `ValueError` | loud, safe |
| `85000 EUR` | `ValueError` | loud, safe |
| `£85,000` | `ValueError` | only `$` is stripped |

`_coerce` removes every comma as a thousands separator, so a European
decimal comma multiplies the value by 100 **silently**. This is worse than
a refusal: the wrong number reaches a reviewer looking entirely plausible,
and salary is a real model feature. For a product with French-locale
clients this is squarely in scope.

Separately, `parse_roster_csv` calls `csv.DictReader` with no delimiter
detection, so a semicolon-delimited export — the default of Excel on a
French or German locale — parses as a single column and is refused.

## Language and locale

| File | What it tests | Expected |
|---|---|---|
| `resignation-letter-written-in-french.txt` | Entirely French prose | Extracts; `note_text` will be French |
| `performance-review-written-in-french.txt` | `Note globale : 4/5` | 4.0 |
| `resignation-letter-mixed-french-and-english.txt` | Code-switching mid-document | Email + date still recovered |

The French files matter beyond curiosity: the sentiment/theme lexicon in
`ml/exit_notes.py` is English-only, so a French note will extract cleanly
and then score 0.00 with no theme.

## Rating scales

| File | What it tests | Expected |
|---|---|---|
| `performance-review-letter-grade-scale-a-to-f.txt` | Letter grade, scale defined inline | A → 5.0 |
| `performance-review-percentage-score-82.txt` | Percentage rather than a scale point | 82% → ~4.1 |
| `performance-review-star-rating-four-of-five.txt` | `★★★★☆` glyphs | 4.0 |
| `performance-review-inverted-scale-1-is-best.txt` | German scale, **1 = best** | ⚠ **Trap** — naive reading gives 1.0; the correct value is 5.0 |

The inverted scale is the one worth watching. A silent misread here writes
the *opposite* of the true rating into a model feature, and `rating_delta`
is a real predictor — so a sign error propagates into training data.

## Dates

| File | What it tests | Expected |
|---|---|---|
| `resignation-letter-ambiguous-date-03-04-2026.txt` | `03/04/2026`, no locale cue | ⚠ Genuinely ambiguous: 3 Apr or 4 Mar |
| `performance-review-fiscal-year-ends-in-june.txt` | FY2025 = Jul 2024 – Jun 2025 | `review_period_end` must be **2025-06-30** |

The fiscal-year case feeds the temporal-leakage guard, which compares the
review period end against the outcome window. A review dated to the wrong
year-end could pass a guard it should fail.

## Structural edge cases

| File | What it tests | Expected |
|---|---|---|
| `performance-review-two-employees-in-one-file.txt` | Two complete reviews concatenated | Schema holds one — the second must not vanish silently |
| `resignation-letter-empty-file.txt` | Zero bytes | Clean refusal, no crash |
| `resignation-letter-whitespace-only.txt` | Whitespace only — non-zero size | Clean refusal |
| `resignation-letter-email-thread-with-quoted-replies.txt` | Resignation buried under two forwards | ⚠ Must attribute to the **resigning employee**, not the last sender |
| `performance-review-very-long-15kb-buried-rating.txt` | ~15 KB filler, rating in the last line | Rating survives the length |
| `performance-review-ocr-garbled-characters.txt` | `rn`→`m`, `l`→`1`, `O`→`0` damage | Recovers email + rating, or refuses honestly |
| `offer-letter-salary-in-tunisian-dinar.txt` | `78 000,000 TND` | Number extracted; currency not modelled |
| `roster-excel-workbook-unsupported-type.xlsx` | Unsupported file type | Refused with the supported-types message, no crash |

The email-thread case is the sharpest of these. Three people appear in the
document and only one is resigning; picking the most prominent email
address attaches the exit to a manager who is not leaving.

## Running it

```bash
# rosters only — no API key needed
# everything else needs COMPANYSIM_LLM_INGEST=1 and a configured provider
python scripts/gen_format_corpus.py      # regenerate (optional)
```

Upload through the Documents page, or drive the API directly. Throttle to
roughly 20–25 requests/minute if extracting the whole set at once.

Suggested order, cheapest signal first:

1. **The 14 roster CSVs** — deterministic, free, and two known defects are
   in there. Check the staged salary values, not just the status.
2. **The four rating-scale files** — especially the inverted scale.
3. **The email thread** — check *which* employee the note attached to.
4. **The PDFs** — particularly the two-column CV.

## Recording results

When a file behaves differently from the table above, the useful record is
what the extractor actually returned, not just that it differed — the
staged `proposed_value`, the stored `rating`, or the refusal reason. A
"needs review" with a specific reason is a success; a plausible-looking
wrong number is the failure worth chasing.
