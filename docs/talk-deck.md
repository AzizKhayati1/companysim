# The talk deck

`reading-the-paperwork.pptx` — 18 slides for a 24-minute technical and
commercial talk, plus 11 backup slides that are not part of the run.

**The slides are deliberately sparse and the notes are deliberately not.**
A slide is looked at, not read: anything longer than a phrase competes with
you, and the room finishes reading before you finish the sentence. So the
slides carry a number, a name, or four short labels — about thirty words
each — and the argument lives in the notes, roughly three words there for
every one on screen.

Ten demo clips are embedded (see `demos/README.md`). Slide 07 carries the
main one; the rest sit in the appendix.

Generated by `scripts/build_talk_deck.py`, which is the source of truth.
Edit the script and re-run rather than hand-editing the `.pptx`, unless the
change is one you would not want regenerated away.

```bash
pip install python-pptx        # not part of any extra; only this script needs it
python scripts/build_talk_deck.py
```

## What you need to fill in

Two slots, both marked in the deck itself so they cannot ship unnoticed.

| Slide | What | Why it is not filled |
|---|---|---|
| 01 | Your name, supervisors, date | Not mine to write |
| 02 | The turnover-cost figure | **Find a real, citable one.** An invented number is the first thing a jury challenges — the slide says so |

Slide 07's demo is now a real recording rather than a placeholder — the
OCR clip, 32 seconds, embedded. It is a recording on purpose: a call to a
cloud model over conference wifi is a two-minute silence waiting to
happen.

## Speaker notes — read this before rehearsing

Every slide's notes are a guideline, not a script. Same six sections in the
same order every time, so a glance down mid-sentence finds your place in
about a second rather than landing in a paragraph you then have to re-scan.

```
══  10:50   ·   2:00  ══      where you are, and how long this slide gets

SAY                           the beats, in order — prompts, not wording
  •  …

THE ONE THING                 if only one sentence survives, this one
  ►  …

POINT AT                      what to gesture at, and when
  ·  …

WATCH OUT                     direction: pace, tone, what not to cut
  !  …

IF ASKED                      the question that is coming, and your answer
  Q  …
  A  …

NEXT  →  10 — principle 3     so you never stall on the transition
```

Not every slide uses every section — an empty one is omitted rather than
left blank, so what is there is always worth reading.

Rehearse from **SAY** until you no longer need it. **THE ONE THING** is
what to fall back on when you are running short: say that sentence and move
on. **IF ASKED** exists so a jury question lands as a prepared answer rather
than as an interruption.

## The screenshots

Six real captures of the running app live in `slide-screenshots/`. They are
dark because the app rendered dark, and the deck is dark to match — a light
deck wrapped around dark product shots reads as two decks stapled together.

To recapture after a UI change, start the app and run Chrome headless:

```bash
chrome --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1560,980 \
  --virtual-time-budget=14000 \
  --screenshot=docs/slide-screenshots/documents.png \
  http://localhost:5173/orgs/9/documents
```

`--virtual-time-budget` matters: without it the capture fires before the
data arrives and you get an empty shell. `--force-device-scale-factor=2`
is what keeps the text sharp when projected.

Two shots need a state no URL reaches — the review split with a document
selected, and the diagnosis modal. Take those manually with the OS
screenshot tool if you want them.

## Timing

The rail in the top-right of each slide shows cumulative time and duration.
It runs to 24:00, leaving a minute inside a 25-minute slot.

If you overrun, cut in this order: slide 04 (compress to two sentences over
the diagram), then slide 12, then — painfully — slide 09. **Never cut slide
16.** Naming your own limits before a jury does is the cheapest credibility
in the talk, and cutting it invites the question anyway.

Act III carries 7:20 of the 24:00 and holds the two ideas the audience
cannot get from the abstract: structural prevention, and the denominator
rule. Rehearse that act against a clock at least twice; everything else can
be improvised.


## Opening it in Canva

The deck imports, with one thing to know in advance.

**Canva does not carry embedded video across from a .pptx.** Every clip
therefore also has its final frame laid in as an ordinary picture
underneath it, so the deck degrades to a screenshot deck rather than to
eleven blank boxes. Where you want the clip back, upload the matching
`.mp4` from `docs/demos/` in Canva and drop it over the still — the still
is already the right size and in the right place.

Two smaller things:

- **Fonts.** The deck asks for Segoe UI. Canva will substitute if it does
  not have it, which changes line lengths slightly. Check slides 09 and 14
  after import — they are the tightest.
- **Size.** 14 MB, well inside Canva's 70 MB import limit, and 29 slides
  against its 100-page limit.

Import with *Create a design → Import file*. Nothing else needs changing.
